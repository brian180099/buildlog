# BuildLog MVP

## 1. 문서 목적

이 문서는 BuildLog의 첫 번째 버전에서 무엇을 만들지 정리한 문서입니다.

MVP는 **사용자에게 꼭 필요한 기능만 먼저 만든 작은 버전**을 뜻합니다. 처음부터 모든 기능을 넣기보다 실제로 사용해 보고, 필요한 기능을 나중에 추가하는 것이 목적입니다.

---

## 2. 서비스 소개

BuildLog는 개인 프로젝트를 진행하며 취업을 준비하는 사람이 사용하는 개발 학습 기록 서비스입니다.

공부한 내용, 해결한 오류, 앞으로 할 일이 메모장과 AI 대화에 흩어지면 나중에 다시 찾기 어렵습니다. BuildLog는 이러한 정보를 한곳에 모아 기록하고, 다시 확인할 수 있게 도와줍니다.

### 한 문장으로 설명하면

> 오늘 배운 것과 해결한 오류, 앞으로 할 일을 한곳에 기록하고 다시 찾는 개인용 학습 노트

---

## 3. 해결하려는 문제

사용자는 다음과 같은 불편을 겪고 있습니다.

- 오늘 무엇을 공부했는지 시간이 지나면 기억하기 어렵습니다.
- 오류 해결 방법을 메모장이나 AI 대화에 남겨도 나중에 위치를 찾기 어렵습니다.
- 프로젝트에서 할 일과 공부할 내용을 한눈에 관리하기 어렵습니다.
- 해결하지 못한 오류를 잊어버리거나, 비슷한 오류를 다시 처음부터 조사하게 됩니다.
- 전날 작성한 내용을 다시 읽고 복습하는 습관을 만들기 어렵습니다.

---

## 4. MVP의 목표

첫 번째 버전에서는 다음 세 가지를 할 수 있어야 합니다.

1. 오늘 공부한 내용을 기록하고 다시 읽을 수 있습니다.
2. 앞으로 할 일을 적고 완료 여부를 확인할 수 있습니다.
3. 오류와 해결 과정을 기록하고, 나중에 검색할 수 있습니다.

서비스를 열었을 때 전날의 기록과 아직 끝나지 않은 일을 바로 확인할 수 있어야 합니다.

---

## 5. 사용자

첫 번째 버전은 다음 사용자를 기준으로 만듭니다.

- 개인 프로젝트를 진행하는 취업 준비생
- 개발 공부 내용을 꾸준히 기록하고 싶은 사람
- 혼자 사용하는 간단한 서비스를 원하는 사람

MVP에서는 여러 사람이 함께 사용하는 기능을 만들지 않습니다. 한 명이 자신의 기록을 관리하는 상황에 집중합니다.

---

## 6. 핵심 기능

### 6.1 공부 기록

사용자는 오늘 공부하거나 작업한 내용을 저장할 수 있습니다.

저장하는 정보:

- 제목
- 내용
- 작성일
- 태그

태그는 기록을 분류하기 위한 짧은 단어입니다. 예를 들어 `Python`, `React`, `알고리즘`처럼 사용할 수 있습니다.

사용자가 할 수 있는 일:

- 새 공부 기록 작성
- 작성한 기록 목록 보기
- 기록 자세히 보기
- 기록 수정
- 기록 삭제

### 6.2 할 일

사용자는 앞으로 공부할 내용이나 프로젝트에서 해야 할 일을 기록할 수 있습니다.

예시:

- 저장 버튼 만들기
- 파이썬 복습하기
- 이력서 수정하기

저장하는 정보:

- 할 일 내용
- 완료 여부
- 마감일(선택 사항)

사용자가 할 수 있는 일:

- 새 할 일 추가
- 완료한 일 체크
- 완료를 취소하고 다시 미완료 상태로 변경
- 남은 일과 완료한 일 구분해서 보기
- 할 일 수정
- 할 일 삭제

### 6.3 오류 기록

사용자는 개발 중 만난 오류와 해결 과정을 따로 기록할 수 있습니다. 아직 해결하지 못한 오류도 먼저 저장할 수 있습니다.

저장하는 정보:

- 오류 제목
- 오류 내용 또는 화면에 표시된 메시지
- 오류가 발생한 상황
- 해결 여부
- 해결 방법
- 태그
- 작성일

사용자가 할 수 있는 일:

- 새 오류 기록 작성
- 해결되지 않은 상태로 저장
- 해결한 뒤 해결 방법 추가
- 해결 여부 변경
- 오류 기록 수정
- 오류 기록 삭제

### 6.4 검색과 분류

사용자는 예전에 작성한 정보를 쉽게 찾을 수 있어야 합니다.

- 제목과 내용에 포함된 단어로 검색
- 공부 기록, 할 일, 오류 기록 중 원하는 종류만 보기
- 태그로 관련 기록 모아 보기
- 오류 기록을 해결 여부에 따라 나눠 보기

### 6.5 어제의 기록

홈 화면에는 전날 작성한 공부 기록을 보여줍니다. 사용자는 서비스를 열자마자 어제 무엇을 공부했는지 다시 읽을 수 있습니다.

전날 기록이 없으면 기록이 없다는 안내와 함께 새 기록을 작성할 수 있는 버튼을 보여줍니다.

### 6.6 로그인

기록을 다른 사람에게 노출하지 않도록 간단한 로그인 기능을 제공합니다.

- MVP에서는 한 명만 사용합니다.
- 회원가입과 여러 사용자 관리는 만들지 않습니다.
- 로그아웃할 수 있습니다.

---

## 7. 화면 구성

### 7.1 로그인 화면

- 아이디와 비밀번호 입력
- 로그인 버튼
- 로그인 실패 시 이해하기 쉬운 안내 표시

### 7.2 홈 화면

사용자가 가장 먼저 보는 화면입니다.

- 어제의 공부 기록
- 아직 완료하지 않은 할 일
- 아직 해결하지 못한 오류
- 공부 기록, 할 일, 오류를 빠르게 추가하는 버튼

### 7.3 공부 기록 화면

- 공부 기록 목록
- 검색창
- 태그 선택
- 새 기록 작성 버튼
- 기록 상세 보기, 수정, 삭제

### 7.4 할 일 화면

- 남은 할 일 목록
- 완료한 할 일 목록
- 완료 여부를 바꾸는 체크 버튼
- 새 할 일 추가, 수정, 삭제

### 7.5 오류 기록 화면

- 전체 오류 목록
- 해결된 오류와 해결되지 않은 오류 구분
- 검색창과 태그 선택
- 새 오류 기록 작성
- 오류 상세 보기, 수정, 삭제

---

## 8. 기본 사용 흐름

### 공부를 마친 뒤

1. 사용자가 로그인합니다.
2. 공부 기록 화면에서 새 기록을 선택합니다.
3. 제목과 내용을 작성합니다.
4. 필요하면 태그를 추가합니다.
5. 저장한 기록을 목록에서 확인합니다.

### 할 일을 관리할 때

1. 사용자가 할 일을 추가합니다.
2. 작업을 마치면 체크 버튼을 누릅니다.
3. 완료한 일은 완료 목록으로 이동합니다.

### 오류를 기록할 때

1. 오류 제목, 오류 내용, 발생 상황을 작성합니다.
2. 아직 해결하지 못했다면 미해결 상태로 저장합니다.
3. 나중에 해결하면 해결 방법을 추가하고 해결 상태로 변경합니다.
4. 비슷한 오류가 발생하면 검색해서 이전 해결 방법을 확인합니다.

### 다음 날 복습할 때

1. 사용자가 BuildLog에 접속합니다.
2. 홈 화면에서 어제 작성한 기록을 읽습니다.
3. 남은 할 일과 해결되지 않은 오류를 확인합니다.

---

## 9. 디자인 방향

BuildLog는 기능을 찾기 쉽고 글을 읽기 편해야 합니다.

- 복잡하지 않은 메모장 같은 화면
- 밝고 차분한 색상
- 버튼 이름을 쉽고 분명하게 표시
- PC와 휴대폰 화면 모두 지원
- 중요한 정보와 자주 사용하는 버튼을 먼저 표시
- 삭제처럼 되돌리기 어려운 작업은 실행 전에 다시 확인

다크 모드는 첫 번째 버전에서 제외하고 나중에 필요할 때 추가합니다.

---

## 10. 첫 번째 버전에서 만들지 않는 기능

MVP의 범위가 너무 커지지 않도록 다음 기능은 제외합니다.

- 여러 사용자의 회원가입과 사용자 관리
- 다른 사용자와 기록 공유
- 댓글과 좋아요
- 사진과 파일 첨부
- 이메일이나 휴대폰 알림
- AI가 내용을 요약하거나 자동으로 분류하는 기능
- 외부 메모장이나 AI 대화 가져오기
- 다크 모드

이 기능들은 BuildLog를 실제로 사용해 본 뒤 필요성이 확인되면 추가합니다.

## 11. 기술 구성

기술을 잘 모르는 사람도 이해할 수 있도록 각 부분의 역할을 함께 설명합니다.

- **프론트엔드: React**  
  사용자가 보는 화면과 버튼을 만듭니다.

- **백엔드: FastAPI**  
  화면에서 받은 요청을 처리하고 기록을 저장하거나 불러옵니다.

- **운영 데이터베이스: Supabase**  
  실제 서비스의 공부 기록, 할 일, 오류 기록을 보관합니다. Supabase가 제공하는 PostgreSQL 데이터베이스를 사용합니다.

- **테스트 데이터베이스: SQLite3**  
  개발 중 자동 테스트와 기능 확인에는 가볍게 실행할 수 있는 SQLite3를 사용합니다. SQLite3는 테스트용이며 실제 서비스 데이터 저장에는 사용하지 않습니다.

프로젝트 폴더는 역할에 따라 다음처럼 나눕니다.

- `frontend/`: 사용자가 보는 화면
- `backend/`: 로그인과 기록 처리
- `database/`: 데이터베이스 관련 설정
- `docs/`: 기획과 사용 방법을 설명하는 문서

처음에는 개발자의 컴퓨터에서 SQLite3로 테스트하며 실행하고, 기본 기능이 안정되면 Supabase에 연결해 실제 환경을 확인한 뒤 인터넷에서 접속할 수 있도록 배포합니다.

## 12. MVP 완료 기준

다음 항목을 모두 직접 사용할 수 있으면 첫 번째 버전이 완료된 것으로 봅니다.

- 한 명의 사용자가 로그인하고 로그아웃할 수 있습니다.
- 공부 기록을 작성하고 목록과 상세 화면에서 확인할 수 있습니다.
- 공부 기록을 수정하고 삭제할 수 있습니다.
- 할 일을 추가하고 완료 여부를 바꿀 수 있습니다.
- 오류를 미해결 상태로 저장한 뒤 해결 방법을 추가할 수 있습니다.
- 제목과 내용으로 기록을 검색할 수 있습니다.
- 태그와 상태를 이용해 원하는 기록만 볼 수 있습니다.
- 홈 화면에서 어제의 기록, 남은 할 일, 미해결 오류를 볼 수 있습니다.
- PC와 휴대폰에서 주요 기능을 불편 없이 사용할 수 있습니다.
- 비밀번호나 데이터베이스 비밀번호 같은 비밀값은 소스 코드에 기록하지 않습니다.

## 13. MVP 이후 확인할 점

첫 번째 버전을 직접 사용하면서 다음 내용을 확인합니다.

- 기록을 작성하는 과정이 번거롭지 않은가?
- 어제의 기록을 실제로 다시 읽게 되는가?
- 원하는 오류 해결 기록을 빠르게 찾을 수 있는가?
- 할 일의 마감일이 실제로 도움이 되는가?
- 태그를 직접 입력하는 방식이 편리한가?
- 알림, 파일 첨부, AI 요약 중 어떤 기능이 가장 필요한가?

이 답을 바탕으로 다음 버전의 기능 순서를 정합니다.
