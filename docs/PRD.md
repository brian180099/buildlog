# BuildLog PRD

## 1. 문서 소개

이 문서는 BuildLog의 첫 번째 버전을 만들기 위한 제작 주문서입니다.

PRD는 **누구를 위해 무엇을 왜 만드는지, 어떤 기능이 어디까지 동작해야 하는지 정리한 문서**입니다. 이 문서는 `docs/mvp.md`에서 정한 범위만 반영합니다. 처음에 정하지 않았던 세부 내용은 사용자의 요청에 따라 추천안으로 확정했습니다.

---

## 2. 서비스 한눈에 보기

### 서비스 이름

BuildLog

### 한 문장 소개

오늘 배운 것과 해결한 오류, 앞으로 할 일을 한곳에 기록하고 다시 찾는 개인용 학습 노트입니다.

### 첫 번째 버전의 핵심 목표

사용자는 BuildLog에서 다음 세 가지 정보를 한곳에 관리할 수 있어야 합니다.

1. 오늘 공부하거나 작업한 내용
2. 앞으로 공부하거나 프로젝트에서 해야 할 일
3. 개발 중 만난 오류와 해결 과정

또한 서비스를 다시 열었을 때 어제의 공부 기록, 남은 할 일, 해결하지 못한 오류를 바로 확인할 수 있어야 합니다.

---

## 3. 누가 사용하는 서비스인가

### 주 사용자

- 개인 프로젝트를 진행하는 취업 준비생
- 개발 공부 내용을 꾸준히 기록하고 싶은 사람
- 복잡하지 않고 혼자 쓰기 편한 서비스를 원하는 사람

### 첫 번째 버전의 사용자 범위

- 한 명이 자신의 기록을 관리합니다.
- 여러 사람이 함께 사용하거나 기록을 공유하지 않습니다.
- 회원가입 기능 없이 정해진 사용자 한 명이 로그인합니다.

---

## 4. 어떤 불편을 해결하려는가

사용자는 공부와 프로젝트를 진행하면서 다음과 같은 불편을 겪습니다.

- 오늘 무엇을 공부했는지 시간이 지나면 기억하기 어렵습니다.
- 메모장과 AI 대화에 내용이 흩어져 있어 다시 찾기 어렵습니다.
- 프로젝트에서 해야 할 일과 공부할 내용을 한눈에 관리하기 어렵습니다.
- 해결하지 못한 오류를 잊어버릴 수 있습니다.
- 비슷한 오류가 다시 생기면 해결 방법을 처음부터 다시 조사하게 됩니다.
- 전날 작성한 내용을 다시 읽고 복습하는 습관을 만들기 어렵습니다.

BuildLog는 공부 기록, 할 일, 오류 기록을 한곳에 모으고 검색할 수 있게 하여 이 문제를 해결합니다.

## 5. 사용자가 기능으로 할 수 있는 일

### 5.1 로그인과 로그아웃

사용자는 자신의 기록을 다른 사람에게 노출하지 않도록 로그인할 수 있습니다.

필요한 동작:

- 아이디와 비밀번호를 입력해 로그인할 수 있습니다.
- 입력한 정보가 맞지 않으면 이해하기 쉬운 실패 안내를 봅니다.
- 로그인한 뒤 로그아웃할 수 있습니다.
- 회원가입과 여러 사용자 관리는 제공하지 않습니다.

정해진 방식:

- 로그인 아이디와 비밀번호는 `.env` 설정 파일에 미리 입력합니다.
- 아이디나 비밀번호를 바꿀 때도 `.env`의 값을 변경합니다.
- 실제 아이디와 비밀번호는 문서나 소스 코드에 기록하지 않습니다.
- 회원가입이나 별도의 계정 설정 화면은 만들지 않습니다.

세부 기준:

- 로그인 상태는 로그인한 날부터 7일 동안 유지합니다.
- 사용자가 로그아웃 버튼을 누르면 로그인 상태는 즉시 끝납니다.
- 7일이 지나면 다시 로그인해야 합니다.

### 5.2 공부 기록

사용자는 오늘 공부하거나 작업한 내용을 기록하고 다시 확인할 수 있습니다.

저장할 정보:

- 제목
- 내용
- 작성일
- 태그

필요한 동작:

- 새 공부 기록을 작성하고 저장할 수 있습니다.
- 저장된 공부 기록을 목록으로 볼 수 있습니다.
- 기록 하나를 선택해 자세한 내용을 볼 수 있습니다.
- 작성한 기록을 수정할 수 있습니다.
- 작성한 기록을 삭제할 수 있습니다.
- 삭제하기 전에는 정말 삭제할지 다시 확인합니다.

세부 기준:

- 제목은 최대 100자, 내용은 최대 20,000자까지 입력할 수 있습니다.
- 작성일은 오늘 날짜가 기본으로 들어가며, 사용자가 다른 날짜로 바꿀 수 있습니다.
- 목록은 작성일이 최근인 기록부터 보여줍니다.
- 작성일이 같으면 나중에 등록한 기록을 먼저 보여줍니다.

### 5.3 할 일

사용자는 앞으로 공부할 내용이나 프로젝트에서 해야 할 일을 관리할 수 있습니다.

예시:

- 저장 버튼 만들기
- 파이썬 복습하기
- 이력서 수정하기

저장할 정보:

- 할 일 내용
- 완료 여부
- 마감일(선택 사항)
- 완료한 시각(완료할 때 시스템이 자동 기록)

필요한 동작:

- 새 할 일을 추가할 수 있습니다.
- 할 일을 완료 상태로 바꿀 수 있습니다.
- 완료한 일을 다시 미완료 상태로 바꿀 수 있습니다.
- 남은 일과 완료한 일을 구분해서 볼 수 있습니다.
- 할 일을 수정할 수 있습니다.
- 할 일을 삭제할 수 있습니다.
- 삭제하기 전에는 정말 삭제할지 다시 확인합니다.

세부 기준:

- 할 일 내용은 최대 200자까지 입력할 수 있습니다.
- 남은 할 일은 마감일이 가까운 순서로 보여주고, 마감일이 없는 일은 그 뒤에 보여줍니다.
- 같은 조건에서는 나중에 등록한 할 일을 먼저 보여줍니다.
- 완료한 할 일은 나중에 완료한 항목부터 보여줍니다.
- 마감일이 지났지만 완료하지 않은 일에는 빨간색으로 `마감 지남`을 표시합니다.

### 5.4 오류 기록

사용자는 개발 중 만난 오류와 해결 과정을 기록할 수 있습니다. 아직 해결하지 못한 오류도 먼저 남겨둘 수 있습니다.

저장할 정보:

- 오류 제목
- 오류 내용 또는 화면에 표시된 메시지
- 오류가 발생한 상황
- 해결 여부
- 해결 방법
- 태그
- 작성일

필요한 동작:

- 새 오류 기록을 작성할 수 있습니다.
- 오류를 미해결 상태로 저장할 수 있습니다.
- 오류를 해결한 뒤 해결 방법을 추가할 수 있습니다.
- 해결 여부를 변경할 수 있습니다.
- 오류 기록을 수정할 수 있습니다.
- 오류 기록을 삭제할 수 있습니다.
- 삭제하기 전에는 정말 삭제할지 다시 확인합니다.

세부 기준:

- 오류 제목은 최대 100자까지 입력할 수 있습니다.
- 오류 내용, 발생 상황, 해결 방법은 각각 최대 10,000자까지 입력할 수 있습니다.
- 해결 상태로 바꾸려면 해결 방법을 반드시 작성해야 합니다.
- 오류 목록은 작성일이 최근인 기록부터 보여줍니다.
- 작성일이 같으면 나중에 등록한 기록을 먼저 보여줍니다.

### 5.5 검색과 분류

사용자는 예전에 작성한 기록을 검색하고 필요한 기록만 골라 볼 수 있습니다.

필요한 동작:

- 제목과 내용에 들어 있는 단어로 기록을 검색할 수 있습니다.
- 공부 기록, 할 일, 오류 기록 중 원하는 종류만 볼 수 있습니다.
- 태그를 선택해 관련 기록만 모아 볼 수 있습니다.
- 오류 기록을 해결 또는 미해결 상태로 나눠 볼 수 있습니다.

세부 기준:

- 한 번의 검색으로 공부 기록, 할 일, 오류 기록을 함께 찾는 통합 검색을 사용합니다.
- 검색 결과는 기록 종류로 나눠 볼 수 있습니다.
- 검색어 앞뒤의 빈칸과 연속된 빈칸은 무시합니다.
- 검색어가 여러 단어이면 모든 단어가 들어 있는 결과를 보여주며, 단어 순서는 상관없습니다.
- 영문 대문자와 소문자는 같은 글자로 처리합니다.
- 태그는 사용자가 직접 입력하고 `Enter` 키로 추가합니다.
- 태그 한 개는 최대 20자이며, 기록 하나에는 최대 5개까지 넣을 수 있습니다.
- 같은 기록에 똑같은 태그를 두 번 넣을 수 없습니다.

### 5.6 어제의 기록과 홈 요약

사용자는 홈 화면에서 다시 확인해야 할 내용을 바로 볼 수 있습니다.

필요한 동작:

- 어제 작성한 공부 기록을 보여줍니다.
- 어제의 공부 기록이 없으면 기록이 없다는 안내를 보여줍니다.
- 기록이 없다는 안내와 함께 새 공부 기록을 작성하는 버튼을 보여줍니다.
- 아직 완료하지 않은 할 일을 보여줍니다.
- 아직 해결하지 못한 오류를 보여줍니다.
- 공부 기록, 할 일, 오류 기록을 빠르게 추가하는 버튼을 보여줍니다.

세부 기준:

- 날짜는 한국 시간(`Asia/Seoul`)을 기준으로 판단합니다.
- 홈에서는 어제의 공부 기록, 남은 할 일, 미해결 오류를 각각 최대 5개까지 보여줍니다.
- 어제의 공부 기록과 미해결 오류는 최근에 등록한 항목부터 보여줍니다.
- 남은 할 일은 마감일이 가까운 항목부터 보여주고, 마감일이 없는 일은 그 뒤에 보여줍니다.
- 홈에 보이지 않는 나머지 항목은 각 기록 화면에서 확인합니다.

## 6. 필요한 화면

### 6.1 로그인 화면

화면에 필요한 요소:

- 아이디 입력칸
- 비밀번호 입력칸
- 로그인 버튼
- 로그인 실패 안내

### 6.2 홈 화면

화면에 필요한 요소:

- 어제의 공부 기록
- 아직 완료하지 않은 할 일
- 아직 해결하지 못한 오류
- 공부 기록 빠른 추가 버튼
- 할 일 빠른 추가 버튼
- 오류 기록 빠른 추가 버튼

### 6.3 공부 기록 화면

화면에 필요한 요소:

- 공부 기록 목록
- 검색창
- 태그 선택 영역
- 새 기록 작성 버튼
- 기록 상세 보기
- 기록 수정 기능
- 기록 삭제 기능

### 6.4 할 일 화면

화면에 필요한 요소:

- 남은 할 일 목록
- 완료한 할 일 목록
- 완료 여부를 바꾸는 체크 버튼
- 새 할 일 추가 기능
- 할 일 수정 기능
- 할 일 삭제 기능

### 6.5 오류 기록 화면

화면에 필요한 요소:

- 전체 오류 목록
- 해결된 오류와 해결되지 않은 오류의 구분
- 검색창
- 태그 선택 영역
- 새 오류 기록 작성 기능
- 오류 상세 보기
- 오류 수정 기능
- 오류 삭제 기능

### 6.6 화면 공통 영역

- 로그인한 뒤 보이는 화면 위쪽에 통합 검색창을 둡니다.
- 검색 결과에서 공부 기록, 할 일, 오류 기록을 종류별로 나눠 볼 수 있습니다.
- PC에서는 왼쪽 메뉴, 휴대폰에서는 아래쪽 메뉴로 홈과 각 기록 화면을 이동합니다.

### 화면 전반의 디자인 원칙

- 복잡하지 않은 메모장 같은 느낌으로 만듭니다.
- 밝고 차분한 색상을 사용합니다.
- 버튼 이름은 쉽고 분명하게 표시합니다.
- PC와 휴대폰 화면에서 모두 사용할 수 있게 만듭니다.
- 중요한 정보와 자주 사용하는 버튼을 먼저 보여줍니다.
- 삭제처럼 되돌리기 어려운 작업은 실행 전에 다시 확인합니다.

세부 기준:

- 흰색과 밝은 회색을 기본 배경으로 사용하고, 주요 버튼에는 차분한 파란색을 사용합니다.
- 완료 또는 해결 상태는 초록색, 마감이 지난 상태는 빨간색으로 구분합니다.
- 글꼴은 기기에 기본으로 설치된 읽기 쉬운 고딕 계열 글꼴을 사용합니다.
- 아이콘은 꼭 필요한 버튼에만 사용하고, 아이콘 옆에 이해하기 쉬운 글자를 함께 표시합니다.
- PC에서는 화면 왼쪽 메뉴로 이동하고, 휴대폰에서는 화면 아래쪽 메뉴로 이동합니다.
- 공부 기록과 오류 기록은 작성할 내용이 많으므로 별도 작성·수정 화면을 사용합니다.
- 할 일은 내용이 짧으므로 현재 화면 위에 뜨는 작은 입력 창에서 추가하고 수정합니다.

## 7. 기본 사용 흐름

### 공부를 마친 뒤

1. 사용자가 로그인합니다.
2. 공부 기록 화면에서 새 기록 작성을 선택합니다.
3. 제목과 내용을 작성합니다.
4. 필요하면 태그를 추가합니다.
5. 저장한 기록을 목록에서 확인합니다.

### 할 일을 관리할 때

1. 사용자가 할 일을 추가합니다.
2. 작업을 마치면 체크 버튼을 누릅니다.
3. 완료한 일은 완료 목록에서 확인합니다.

### 오류를 기록할 때

1. 오류 제목, 오류 내용, 발생 상황을 작성합니다.
2. 아직 해결하지 못했다면 미해결 상태로 저장합니다.
3. 나중에 해결하면 해결 방법을 추가하고 해결 상태로 변경합니다.
4. 비슷한 오류가 생기면 검색해서 이전 해결 방법을 확인합니다.

### 다음 날 복습할 때

1. 사용자가 BuildLog에 접속합니다.
2. 홈 화면에서 어제 작성한 공부 기록을 읽습니다.
3. 남은 할 일과 해결되지 않은 오류를 확인합니다.

## 8. 첫 번째 버전의 완성 기준

아래 항목이 모두 실제로 동작하면 첫 번째 버전이 완성된 것으로 봅니다.

### 계정

- 한 명의 사용자가 로그인하고 로그아웃할 수 있습니다.
- 비밀번호와 데이터베이스 비밀번호 같은 비밀값이 소스 코드에 들어 있지 않습니다.

### 공부 기록

- 공부 기록을 작성하고 저장할 수 있습니다.
- 저장한 기록을 목록과 상세 화면에서 확인할 수 있습니다.
- 기록을 수정하고 삭제할 수 있습니다.

### 할 일

- 할 일을 추가할 수 있습니다.
- 완료 여부를 바꿀 수 있습니다.
- 남은 일과 완료한 일을 구분해서 볼 수 있습니다.
- 할 일을 수정하고 삭제할 수 있습니다.

### 오류 기록

- 오류를 미해결 상태로 저장할 수 있습니다.
- 나중에 해결 방법을 추가하고 해결 상태로 바꿀 수 있습니다.
- 오류 기록을 확인하고 수정하고 삭제할 수 있습니다.

### 검색과 분류

- 제목과 내용에 들어 있는 단어로 기록을 검색할 수 있습니다.
- 태그를 이용해 원하는 기록만 볼 수 있습니다.
- 오류를 해결 여부에 따라 나눠 볼 수 있습니다.
- 원하는 기록 종류만 골라 볼 수 있습니다.

### 홈과 화면 지원

- 홈에서 어제의 공부 기록을 볼 수 있습니다.
- 홈에서 남은 할 일과 미해결 오류를 볼 수 있습니다.
- PC와 휴대폰에서 주요 기능을 불편 없이 사용할 수 있습니다.

## 9. 이번에 만들지 않는 기능

다음 기능은 첫 번째 버전에 포함하지 않습니다.

- 여러 사용자의 회원가입과 사용자 관리
- 다른 사용자와 기록 공유
- 댓글과 좋아요
- 사진과 파일 첨부
- 이메일이나 휴대폰 알림
- AI가 내용을 요약하거나 자동으로 분류하는 기능
- 외부 메모장이나 AI 대화의 기록 가져오기
- 다크 모드

이 기능들은 첫 번째 버전을 직접 사용해 본 뒤 필요성이 확인되면 검토합니다.

## 10. 정해진 기술 구성

- **프론트엔드: React**  
  사용자가 보는 화면과 버튼을 만듭니다.

- **백엔드: FastAPI**  
  화면에서 받은 요청을 처리하고 기록을 저장하거나 불러옵니다.

- **운영 데이터베이스: Supabase**  
  실제 서비스의 공부 기록, 할 일, 오류 기록을 보관합니다. Supabase가 제공하는 PostgreSQL 데이터베이스를 사용합니다.

- **테스트 데이터베이스: SQLite3**  
  개발 중 자동 테스트와 기능 확인에는 SQLite3를 사용합니다. 실제 서비스 데이터는 SQLite3가 아니라 Supabase에 저장합니다.

- **프로젝트 실행 순서**  
  먼저 개발자의 컴퓨터에서 SQLite3를 이용해 기능을 테스트합니다. 기본 기능이 안정되면 Supabase 연결 환경에서도 같은 기능이 동작하는지 확인하고, 그다음 인터넷에서 접속할 수 있도록 배포합니다.

## 11. 추천안으로 확정한 전제

다음 내용은 처음에는 정하지 않았지만, 사용자의 요청에 따라 추천안으로 확정했습니다.

1. 로그인 상태는 7일 동안 유지하고, 로그아웃하면 즉시 끝냅니다.
2. 공부 기록의 작성일은 오늘이 기본이며 사용자가 바꿀 수 있습니다.
3. 공부 기록과 오류 기록은 최근 작성일 순으로 보여줍니다.
4. 남은 할 일은 마감일이 가까운 순서로, 완료한 할 일은 최근 완료 순으로 보여줍니다.
5. 마감일이 지난 미완료 항목에는 빨간색으로 `마감 지남`을 표시합니다.
6. 오류를 해결 상태로 바꾸려면 해결 방법을 반드시 작성해야 합니다.
7. 공부 기록, 할 일, 오류 기록을 한 번에 찾는 통합 검색을 사용합니다.
8. 검색은 불필요한 빈칸과 영문 대소문자를 무시하고, 입력한 모든 단어가 포함된 결과를 찾습니다.
9. 태그는 직접 입력하며 한 기록에 최대 5개까지 넣을 수 있습니다.
10. 날짜는 한국 시간(`Asia/Seoul`)을 기준으로 판단합니다.
11. 홈의 각 목록은 최대 5개까지 보여줍니다.
12. 제목, 본문, 할 일, 태그 등 입력 항목별 최대 글자 수를 적용합니다.
13. 밝은 배경과 차분한 파란색을 중심으로 한 단순한 디자인을 사용합니다.
14. PC는 왼쪽 메뉴, 휴대폰은 아래쪽 메뉴를 사용합니다.
15. 공부 기록과 오류 기록은 별도 화면에서, 할 일은 작은 입력 창에서 작성하고 수정합니다.
